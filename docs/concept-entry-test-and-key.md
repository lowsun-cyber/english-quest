# Концепция: вступительное испытание, ключ ученика и оплата без лишних данных

Статус: **черновик для обсуждения** (12.10.2026). Сделано по концепции: испытание на устройстве без сервера (раздел 6, шаг 1 раздела 11) — запись 23 паспорта; ключ семьи и оплата не делались. Юридические утверждения помечены «проверить с юристом» — это не юридическое заключение.

## 1. Гипотеза владельца

Ребёнок 2–4 класса проходит вступительное испытание → игра предлагает программу прохождения → ребёнку выдаётся ключ (ID), с которым он входит. Родитель сам создаёт профили на основе ключа. После испытания — необязательная почта для результатов. Цель — минимум персональных данных, лёгкая политика конфиденциальности, больше автоматизации (без ручного создания учёток админом).

## 2. Короткий вывод

Гипотеза жизнеспособна и хорошо ложится на то, что уже есть: прогресс и так живёт на устройстве, сервер нужен только для синхронизации, а в API уже есть одноразовые коды подключения устройства (`/claim`) и постоянные ключи, хранимые как хэш.

Главная мысль, которая сильнее «ключа вместо логина»: **испытание и всё, что ему нужно, работает на устройстве без сервера.** Данные появляются у нас только в момент, когда родитель сам решает «сохранить прогресс» или «оплатить». До этого мы не обрабатываем ничего.

Политику конфиденциальности убрать не выйдет, но её можно свести к одной странице с короткой таблицей «что храним» — без имён, дат рождения, школ, фото и голоса.

## 3. Путь пользователя

```
Сайт / приложение
  └─ «Пройти испытание стража ворот» — без входа, без данных
       ├─ выбор класса (2 / 3 / 4) — крупные кнопки, озвучено
       ├─ 10–15 заданий, 6–8 минут, всё на устройстве
       └─ итог: карта навыков + стартовые локации (программа)
            ├─ ребёнку: «Ворота открыты!» и первая локация
            └─ взрослому (за «родительскими воротами»):
                 ├─ разбор по-русски: что освоено, что учить
                 ├─ «Сохранить картинкой / PDF» — без почты
                 └─ «Сохранить прогресс на сервере» → выдаётся ключ
                      ├─ карточка с ключом и QR (распечатать / сфотографировать)
                      ├─ почта — по желанию (только здесь): восстановление ключа и письмо с итогом
                      └─ «Открыть полный квест» → оплата у провайдера
```

Без сохранения на сервере игра продолжает работать как сейчас — на одном устройстве.

## 4. Данные: что, где и зачем

| Данные | Где хранятся | Зачем | Срок |
|---|---|---|---|
| Имя или прозвище, аватар | **только на устройстве** | «Кто играет?» | пока есть на устройстве |
| Записи голоса | только на устройстве (как сейчас) | «послушай себя» | — |
| Ответы и результат испытания | на устройстве; на сервер — только при сохранении | программа, разбор | вместе с прогрессом |
| Ключ семьи | у родителя (карточка); на сервере — только хэш | вход, новое устройство | — |
| Прогресс ребёнка | сервер в РФ, привязан к безликому номеру | синхронизация, работа на нескольких устройствах | до удаления или N месяцев неактивности |
| Ключи устройств | сервер, только хэш (как сейчас) | не вводить ключ каждый раз | до выхода/отзыва |
| Почта родителя | сервер, **только если указал** | восстановление ключа, письмо с результатом | до удаления |
| Лицензия | сервер: номер заказа, тариф, срок, статус | доступ к платной части | срок хранения учёта — уточнить у бухгалтера |
| Данные плательщика и карты | **у платёжного провайдера**, не у нас | оплата, чек | по правилам провайдера |
| Счётчики для статистики | сервер, без номеров учеников | «сколько прошли испытание / оплатили» | агрегаты |

Выводы:
- Имя на сервер в домашнем (B2C) сценарии не отправляется. На сервере ребёнок — «Игрок 1» или прозвище, которое сгенерировала игра («Лис-47»). Для школ (B2B) имя у учителя остаётся, как сейчас.
- Безличный номер + прогресс в российской практике всё равно лучше считать персональными данными: как только рядом появляются почта, оплата или IP, человека можно определить. Поэтому ориентир не «ПДн нет», а «ПДн минимальные, без особых категорий и без биометрии» (голос не уходит с устройства и не используется для узнавания).
- Нужна кнопка «Удалить всё» для родителя по ключу и автоудаление неактивных аккаунтов **через 12 месяцев** (решение владельца) без входа и синхронизации; у оплативших отсчёт — с конца последнего оплаченного периода. За 30 дней — письмо-предупреждение, если почта есть, и баннер у взрослого в приложении.

Что всё равно понадобится (проверить с юристом):
- короткая политика обработки ПДн на сайте;
- согласие родителя (ребёнку до 14 лет) — отдельной галочкой/документом в момент «Сохранить прогресс» и отдельно на почту; по последним изменениям 152-ФЗ согласие должно быть отдельным от других документов;
- уведомление Роскомнадзора об обработке ПДн;
- хранение в РФ — уже выполнено (Спринтхост);
- распознавание речи браузером (Chrome отправляет звук наружу) — по-прежнему только с явного согласия родителя.

## 5. Ключ ученика (семьи)

### Кто чем владеет
- **Ключ семьи** — один на семью, у родителя. Даёт: добавить ребёнка, подключить устройство, увидеть разбор, оплатить, удалить данные.
- **Ребёнок ключ не вводит.** Устройство подключается один раз (родитель вводит ключ или сканирует QR), дальше работает постоянный ключ устройства — механизм уже есть.
- Новое устройство: ввести ключ или отсканировать QR с карточки; либо одноразовый короткий код с уже подключённого устройства (как сейчас в `/claim`).

### Формат
- 4 простых русских слова + 2 цифры: `ЛИСА-РАКЕТА-ПИРОГ-ЗОНТ-47`. Словарь ≈ 2000 конкретных, безобидных существительных, без похожих пар.
- Стойкость: 4 слова из 2048 и 2 цифры ≈ 50 бит — при ограничении попыток подобрать чужой ключ, даже «любой из многих», непрактично. Три слова (≈ 40 бит) уже на грани при массовом переборе с многих адресов.
- Ввод терпим к регистру, «ё/е», пробелам и дефисам. Слова легко продиктовать по телефону бабушке.
- На сервере только хэш: «показать ключ ещё раз» невозможно — можно только **выпустить новый** с подключённого устройства или по почте (старый перестаёт работать).

### Если ключ потерян
1. Есть подключённое устройство → «Для взрослых» → «Новый ключ».
2. Указана почта → «Забыли ключ?» → письмо со ссылкой на новый ключ.
3. Была оплата → родитель присылает чек провайдера; по номеру заказа находим семью и выпускаем новый ключ (почту мы при этом не храним — она у провайдера и у родителя).
4. Ничего нет → бесплатный прогресс потерян. Об этом честно сказать на карточке крупно.

### Злоупотребления
- Ключ раздали друзьям → предел активных устройств на семью (например, 5), список устройств и «отключить» у родителя.
- Перебор → общий и по-адресный лимит попыток (таблица `fails` уже есть), задержка после ошибок.

## 6. Вступительное испытание

Опирается на то, что уже записано в `docs/design-v2/CONCEPT.md` («страж ворот», граф навыков, коды ошибок) и `docs/curriculum-map.md` (навыки G2–G4).

- **Без чтения инструкций взрослым:** каждое задание озвучено, первое — пример с подсказкой; задания «послушай — нажми картинку», «собери слово», «выбери фразу».
- **Адаптивное, но простое и предсказуемое:** старт с середины выбранного класса; по каждому блоку навыков 1–2 задания; верно → шаг выше, неверно → шаг ниже или соседний навык. Остановка — после 12–15 заданий или ~8 минут.
- **Защита от угадывания:** на навык минимум 2 задания разных типов; «освоено» только при двух верных. Вариант «не знаю» без штрафа — честнее, чем случайный выбор.
- **Без ощущения провала:** страж «открывает ворота» при любом результате; ребёнку — награда и первая локация, разбор — только взрослому.
- **Итог** — не «уровень A1», а стартовая точка: навыки «освоено / проверим в игре / учим», открытые регионы, план на 10–15 минут в день. Называть уровни по CEFR без проверки на реальных детях нельзя.
- **Один ребёнок — один класс** (решение владельца): испытание проверяет навыки только выбранного класса. Если всё освоено, программа ведёт в последние регионы класса и «Шахты», а не в следующий класс. Класс в профиле меняет взрослый (например, в сентябре); после смены — новое стартовое испытание, бесплатный регион при этом не добавляется.
- **Повтор:** короткие контрольные точки в начале каждого оплаченного периода и по кнопке у взрослого; программа пересчитывается. Подробнее — раздел 9.
- **Проверка:** до запуска — пилот на детях из школы (сколько длится, где бросают, совпадает ли итог с мнением учителя).

## 7. «AI» — где он есть и где его нет

- **В рантайме LLM не вызывается.** Испытание и выбор программы — детерминированные правила по банку заданий и графу навыков. Плюсы: работает офлайн, предсказуемо, бесплатно в обслуживании, данные ребёнка не уходят третьей стороне (в том числе за границу — это была бы трансграничная передача со своими требованиями).
- **AI — на этапе подготовки:** банк заданий, объяснения ошибок и посылки Dr. Harlow готовятся с AI и проверяются человеком, как сейчас.
- **Формулировки для сайта:** «программа подбирается по результатам испытания»; не «AI-сервис», не «нейросеть подберёт» (правило проекта).

## 8. Оплата

Решение владельца (12.10.2026): продавец — **ИП на налоге на профессиональный доход (НПД)**; бесплатно — **испытание и регион, который оно рекомендовало**, остальное платно; покупка — **на периоды**, при условии, что хватит нового контента под уровень (раздел 9).

- **Провайдер** показывает свою платёжную форму и хранит данные плательщика. Нам приходит уведомление (webhook): номер заказа, сумма, статус. Заказ создаём со ссылкой на безличный номер семьи — без имени ребёнка.
- **Провайдер под НПД.** Нужен тот, кто работает с плательщиками НПД и сам регистрирует чек в «Мой налог» после оплаты (такие решения есть, например, у ЮKassa и Robokassa; проверить актуальные условия и комиссии на момент интеграции). Тогда не нужно вручную пробивать каждую продажу.
- **Чек.** На НПД онлайн-касса по 54-ФЗ не нужна — чек формируется в «Мой налог». Покупателю его нужно передать, обычно на почту или телефон. Если почту для чека собирает форма провайдера, мы её не получаем и не храним. Проверить у провайдера, как это устроено именно у него.
- **Ограничения НПД, которые касаются плана:**
  - предел дохода — 2,4 млн ₽ в год; при росте понадобится переход на УСН (тогда онлайн-касса и чеки по 54-ФЗ — провайдер с «чеками от провайдера» снимет и это);
  - нельзя нанимать сотрудников по трудовому договору — для пилота не мешает, для стартапа станет поводом сменить режим;
  - продажа школам (юрлицам) разрешена, ставка выше (6 % против 4 % с физлиц), в чеке — ИНН покупателя;
  - продаём доступ к игре и цифровому контенту, а не «образовательные услуги» — формулировку оферты проверить с юристом.
- **Оферта** на сайте: что покупается, срок доступа, возврат. Принятие — галочкой на «родительских воротах» перед оплатой.
- **Модель — разовая оплата за период, без автосписаний.** На старте — **«четверть»** (решение владельца; ≈ 3 месяца, совпадает со школьной четвертью и с сезонным выпуском контента). **Позже** (решение владельца) — годовая покупка со скидкой, когда темп сезонных выпусков подтвердится, и **отдельные условия для организаций** (школы, кружки, репетиторы): лицензия на число учеников или класс, оплата по счёту, коды для учеников. За 7 и за 1 день до конца — напоминание у взрослого в приложении (и письмом, если почта указана). После конца — бесплатная часть и весь прогресс остаются, платные регионы закрываются до продления. Автоплатёж требует хранить способ оплаты у провайдера и соблюдать правила об отмене — для старта лишнее.
- **Ключ как лицензия:** лицензия висит на семье, а не на устройстве; возврат платежа (webhook) снимает лицензию.
- **«Родительские ворота»** перед оплатой и вводом почты — ребёнок не должен случайно попасть на форму.
- **Что бесплатно:** испытание с итогом и программой и **один регион — тот, с которого испытание советует начать**. Так бесплатная часть всегда по силам ребёнку и показывает игру на его уровне. Регион фиксируется при первом испытании, повтор испытания не открывает новый бесплатный регион. Платно — остальные регионы, посылки, клиника целиком, новые сезонные выпуски.
- **Момент покупки** — после испытания («вот программа») и когда бесплатный регион пройден («дальше по программе — …»).
- **Промокоды и коды организаций** — тот же механизм лицензии: для пилота сразу, для платных тарифов организаций — позже. Продажа организациям на НПД возможна, но объём быстро упрётся в предел 2,4 млн ₽ в год — к этому моменту, скорее всего, понадобится УСН.

## 9. Новый контент на оплаченный период и периодические проверки

Покупка на периоды честна, только если в каждом периоде у ребёнка есть новое по его уровню. Поэтому ниже — как этого добиться без вызова AI в рантайме и без отправки данных ребёнка третьим лицам.

### Что есть сейчас
- Основная программа в `content.js` — темы Spotlight 2–4 и испытания (см. `docs/curriculum-map.md`).
- Посылки Dr. Harlow (запись 19 паспорта): **ручной** путь — взрослый копирует выгрузку прогресса без имени, отдаёт модели, проверяет ответ и отправляет одному ученику. Для домашних покупателей без учителя так не масштабируется.
- Новые слова в посылках звучат голосом устройства — записи тем же голосом делаются отдельно (`tools/gen-voices.mjs`).

### Где на самом деле узкое место
Сами задания AI делает быстро. Дольше всего — проверка человеком, озвучка, рисунки и прогон тестов. Поэтому контент выгоднее выпускать **партиями на всех**, а подбирать **индивидуально**:

1. **Сезонный выпуск** раз в период (≈ четверть): набор пакетов локаций и особых квестов на каждую ступень графа навыков, по 2–4 класс. Готовится с AI заранее, проверяется, озвучивается тем же голосом, проходит тесты и выкладывается обычной выкладкой. У всех одинаковый, работает офлайн.
2. **Подбор под ребёнка — на устройстве, правилами:** из основной программы и сезонных пакетов игра выбирает то, что соответствует его карте навыков и ошибкам, и повторяет трудное по интервалам. Это и есть «персональная программа»; она не требует ни генерации, ни сервера.
3. **Что делать в следующем выпуске**, решают обобщённые данные: какие навыки и коды ошибок чаще всего «учим» по итогам проверок. На сервер уходят только счётчики по кодам навыков, без номеров учеников. Ни одна модель не видит данных конкретного ребёнка.
4. **Посылки Dr. Harlow под одного ученика** остаются для учителей и репетиторов (B2B), где взрослый и так смотрит прогресс.

### Периодические проверки
- **Стартовое испытание** — 12–15 заданий (раздел 6).
- **Контрольная точка** в начале каждого оплаченного периода и по кнопке у взрослого — короче, 5–8 заданий: в основном навыки «учим» и «проверим в игре», плюс 1–2 на закрепление освоенного. Подаётся как встреча со стражем у ворот нового сезона, без оценки «сдал / не сдал».
- **Между проверками** карта навыков обновляется сама по ходу игры (мастерство и коды ошибок уже считаются). Проверка нужна, чтобы подтвердить и поправить картину, а не начинать с нуля.
- **Итог** — пересчёт программы: что открыть, что повторить, какие сезонные пакеты показать первыми; взрослому — короткое сравнение «было / стало» по-русски.

### Достаточно ли контента — как проверить до продажи периодов
- На пилоте измерить, сколько заданий в неделю реально проходит ребёнок за 10–15 минут в день, и сравнить с объёмом основной программы для каждой ступени.
- Сделать один сезонный выпуск целиком (подготовка → проверка → озвучка → выкладка) и засечь время. Если на выпуск уходит больше, чем длится период, продавать сначала только «учебный год» на основной программе, а сезоны — по мере готовности.
- Пока сезонных выпусков нет, честная формулировка для родителей — «доступ ко всем регионам и обновлениям на период», без обещания «новые задания каждую неделю».

## 10. Совместимость со школами (B2B)

В сервере уже есть: платформа → организация → администратор / учитель → ученик.

- Семья = организация типа «семья»; родитель — её администратор, но входит по ключу, а не по почте и паролю.
- Ученики школы тоже могут входить по ключу-карточке вместо логина и пароля: учитель печатает карточки на класс. Один механизм для обеих веток.
- Данными школьного ученика распоряжается школа (договор, её согласия). Связь «школьный ученик ↔ семья» — позже и только с согласия родителя; на старте — раздельно.
- Владелец платформы видит только агрегаты, не прогресс конкретных детей семей.

## 11. Порядок внедрения (предложение)

1. **Испытание на устройстве** без сервера: банк заданий, правила, разбор, «сохранить картинкой». Пилот в школе. Сразу даёт пользу; мини-диагностика на сайте Logiqa — позже.
2. **Ключ семьи:** «Сохранить прогресс», карточка с QR, подключение устройств, «Удалить всё», почта по желанию, политика и согласие.
3. **Оплата на периоды:** провайдер под НПД, лицензия со сроком, напоминания, промокоды. Параллельно — первый сезонный выпуск как проверка темпа (раздел 9).
4. **Контрольные точки** в начале периода и сбор обобщённой статистики навыков.
5. **Школы:** карточки с ключами для класса, коды школы.
