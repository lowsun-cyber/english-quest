# Сервер English Quest

Хранит прогресс учеников и обслуживает админ-панель сайта (`/admin/`): ученики, репетиторы, прогресс, домашние задания, выгрузка в PDF. Обычный PHP 8.1+ и MySQL — работает на виртуальном хостинге (сейчас Спринтхост) и без изменений переедет на VDS.

```
server/
  public/       ← веб-папка API: index.php и .htaccess
  src/app.php   ← весь код API
  bin/setup.php ← установка и служебные команды (по SSH)
  config.php    ← пароли и настройки (создаётся из config.example.php, в git не попадает)
```

## Установка на Спринтхост (один раз)

Сервер живёт в папке `/api` поддомена: **`https://quest.logiqa.ru/api/`**. Корень поддомена остаётся свободным — позже туда можно перенести само приложение (тогда оно и данные будут на одном адресе в России).

1. **База.** Панель → «Базы данных MySQL» → создать базу. Запишите имя базы, пользователя и пароль.
2. **PHP.** Панель → «Сайты» → `quest.logiqa.ru` → выбрать **PHP 8.3** (подойдёт любая от 8.1). HTTPS на поддомене уже включён.
3. **Файлы.** На Спринтхосте папка поддомена (`quest`) — это и есть веб-папка сайта `quest.logiqa.ru`; создавать в ней `public_html` не нужно. Загрузить по SFTP (или файловым менеджером панели):
   ```
   <папка сайта logiqa.ru>/public_html/quest/api/   ← содержимое server/public: index.php и .htaccess
   <папка сайта logiqa.ru>/eq-server/                ← server/src, server/bin, server/.htaccess и config.php
   ```
   Главное: `eq-server` лежит **выше** веб-папок (рядом с `public_html` основного сайта), а не внутри `public_html` или `quest` — так код и пароль базы не открыть из браузера. `index.php` сам найдёт `eq-server` на несколько уровней выше. Если папка не найдена, `https://quest.logiqa.ru/api/` так и ответит: «Не найдена папка eq-server».
   Скрытые файлы (`.htaccess`) файловый менеджер может не показывать — проверьте, что они загрузились.
4. **Настройки.** В `eq-server/config.php` вписать базу (`mysql:host=localhost;dbname=…;charset=utf8mb4`), пользователя, пароль и любую длинную случайную строку в `secret`.
5. **Первый запуск** (по SSH):
   ```bash
   cd <папка сайта logiqa.ru>/eq-server
   php -v                        # должна быть 8.1+; если нет — php8.3 вместо php
   php bin/setup.php init "Мои ученики" "Ваше имя"
   ```
   Команда создаст таблицы, организацию и владельца и покажет **код входа** в админ-панель (`адрес сайта/admin/`). Остальные учётные записи — репетиторов и администраторов — создаются уже в самой панели.
6. **Проверка:** `https://quest.logiqa.ru/api/` должен ответить `{"app":"english-quest","ok":true}`.
7. Адрес сервера указан в `js/config.js` (`https://quest.logiqa.ru/api`): в приложении есть раздел «Сервер учителя», а админ-панель — по адресу сайта `/admin/`.

## Сайт на quest.logiqa.ru и автоматическая выкладка

После успешных тестов GitHub Actions выкладывает по SFTP всё сразу: сайт в `public_html/quest/`, код сервера
в `eq-server/src` и `eq-server/bin`, `api/index.php` и `api/.htaccess`. Загружаются только изменённые файлы:
список прошлой выкладки с контрольными суммами хранится в `domains/logiqa.ru/eq-deploy/manifest.json`, вне сайта.
Удаляется только то, что раньше выложила сама выкладка. `config.php` и другие файлы, положенные вручную, не трогаются.
Страницы `.html` загружаются последними, после проверки сайт и сервер опрашиваются, а версия `index.html` сверяется.

Настройка один раз:

1. **Пароль SFTP в секреты репозитория** — набрать в своём терминале (ввод не отображается и никуда, кроме GitHub, не попадает):
   ```bash
   gh secret set SPRINTHOST_PASSWORD
   ```
   Вместо пароля можно дать ключ: `gh secret set SPRINTHOST_SSH_KEY < путь_к_закрытому_ключу` (открытый ключ должен быть добавлен на хостинге).
2. **Переменные репозитория** (Settings → Secrets and variables → Actions → Variables): `SPRINTHOST_USER` (логин),
   `SPRINTHOST_KNOWN_HOSTS` (вывод `ssh-keyscan <адрес>`), и последней — `SPRINTHOST_HOST` (адрес): она включает выкладку.
   Пути по умолчанию: `SPRINTHOST_PATH=domains/logiqa.ru/public_html/quest`, `SPRINTHOST_SERVER_PATH=domains/logiqa.ru/eq-server`,
   `SPRINTHOST_STATE_PATH=domains/logiqa.ru/eq-deploy`; при нестандартном порте — `SPRINTHOST_PORT`.

Пока `SPRINTHOST_HOST` не задана, шаг выкладки на хостинг пропускается.

Выложить с компьютера (нужен `lftp`; `--dry-run` — только показать, что изменится):
```bash
DEPLOY_URL=sftp://ЛОГИН@АДРЕС SITE_PATH=domains/logiqa.ru/public_html/quest SERVER_PATH=domains/logiqa.ru/eq-server STATE_PATH=domains/logiqa.ru/eq-deploy node tools/deploy-hosting.mjs --dry-run
```

## Пароли и почта

Взрослые входят по почте и паролю, ученики — по логину и паролю (в приложении: «Для репетитора и родителей» → «Сервер учителя» → «Вход по логину»). Администратор выдаёт доступ при создании учётной записи: письмо-приглашение (пароль человек задаёт сам) или временный пароль. «Забыли пароль?» присылает ссылку на почту (у ученика — на почту родителя; родитель при этом даёт согласие на обработку данных ребёнка).

Чтобы письма уходили:

1. В панели хостинга создайте ящик `noreply@logiqa.ru` и включите для домена SPF и DKIM (раздел почты).
2. В `eq-server/config.php` добавьте (образец — `config.example.php`):
   ```php
   'app_url' => 'https://quest.logiqa.ru/',
   'mail' => [
     'transport' => 'smtp',
     'host' => 'SMTP-сервер из настроек почты хостинга',
     'port' => 465,
     'user' => 'noreply@logiqa.ru',
     'password' => 'пароль ящика',
     'from' => 'noreply@logiqa.ru',
     'from_name' => 'English Quest',
   ],
   ```
   Если SMTP не заработает, можно `'transport' => 'mail'` (отправка средствами PHP; письма чаще попадают в спам).
3. Проверка: в админ-панели «Мои входы» → укажите свою почту → выйдите → «Забыли пароль?».

Пока почта не настроена, приглашение сообщит об ошибке — выдавайте временные пароли.

## Служебные команды

```bash
php bin/setup.php code    # новый код входа для владельца (если сменили устройство)
php bin/setup.php users   # список взрослых
```

## Резервная копия

Всё хранится в базе MySQL. В панели Спринтхоста включите ежедневные резервные копии базы или делайте выгрузку `mysqldump` по расписанию (cron).

## Переезд на VDS

Скопировать папку сервера и выгрузку базы (`mysqldump` → `mysql`), настроить nginx + PHP-FPM (адрес `/api` → `public/index.php`), поменять `dsn` в `config.php`, перенаправить поддомен на новый адрес. Код менять не нужно. Можно перейти и на PostgreSQL: SQL написан переносимо, поменяется только `dsn`.
